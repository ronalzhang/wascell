# 2026-10-24 网站内存与转储磁盘事故

## 已确认根因

旧统计实现每次请求都读取、解析整份 stats.json，随后把完整快照放入无上限写入队列。写入吞吐跟不上请求突发时，多个大对象同时保留，最终在 JSON.parse 中达到 Node 约 1.87 GB 堆上限并 SIGABRT。Apport 将崩溃进程写为约 2.4 GB core，重复崩溃导致磁盘耗尽。

旧函数隔离复现：500 次更新积压 499 份快照。生产统计文件检查时约 8.63 MB、14164 个 IP、361 天，单日路径最多 2792 项；文件在旧并发写入下还会发生计数覆盖。PM2 日志中最早保留的 SIGABRT 记录为 2026-06-02，10 月上旬及最近一周持续发生。事故不是最近一周才引入的缺陷。

最近一周日志存在 .env、.git/config 探测和 gitdump 自动扫描，10 月 24 日最多一个小时约 1337 个请求。扫描会触发并放大统计缺陷；仅凭这些请求不能断言操作系统已被植入恶意程序。进程检查未发现从 /tmp、/var/tmp、/dev/shm 运行或可执行文件已删除的进程，这也不等价于完整取证后排除入侵。

## 修复与验证

- 单进程共享统计快照，每秒合并原子落盘；取消每请求整文件解析和无上限写入队列。请求路径去掉查询参数；新增 IP、单日路径和天数有上限。历史统计先保留，不直接覆盖损坏文件。
- 原始访问日志使用 1 MB 有界缓冲及 10 MB × 7 轮转归档。过载时允许原始诊断日志丢弃，总访问计数仍同步累计；既有历史日志不自动删除。
- 静态资源白名单阻止服务器源码、部署脚本、统计、日志和 core 下载。此前 app.js、stats.json、access.log、deploy.sh 均可匿名访问。
- 旧部署脚本中的管理员密码与生产相同，已轮换管理员密码和会话密钥；旧会话失效。新密码保存于本机 macOS 钥匙串，服务 arksoma.com/admin-pro，账户 ARKSOMA owner。不得在聊天、文档或命令输出中打印。
- 启动脚本只约束网站：Node 堆 256 MB、PM2 RSS 重启阈值 384 MB、core limit 0、coredump_filter 0。Claude 的 4 GiB 转储守卫保留，最新 root 保护的诊断转储保留。
- 依赖审计发现 body-parser、multer 两项高危拒绝服务漏洞，已在既有版本范围内升级，官方 npm audit 为 0 漏洞。
- 本地和服务器测试 82/82，风险脚本通过。真实统计副本隔离测试 10000 次更新计数准确，约 396 ms，RSS 81→95 MB；未修改生产业务数据。
- 上线后网站进程约 90–120 MB；100 次回环页面请求 P95 259 ms，期间共享主机有其他任务造成的换页压力。两个后台入口与公开 API 正常；管理员新密码登录和统计 API 200，未认证受保护接口 401，敏感静态文件 404。手机首页和预约弹窗无控制台错误，未提交生产申请。
