# ARKSOMA 客户服务与伙伴运营闭环

依据[双后台方案](../specs/2026-11-21-arksoma-partner-incentive-admin-design.md)落地。目标是让管理员从官网意向进入跟进、确认、签约、收退核对和交付，并让运营项目有可直接编辑的业务样板。沿用客户台账、官网项目目录、订单流水及伙伴预算。

| 任务 | 做法 | 验收 |
| --- | --- | --- |
| 运营项目 | 管理员可采用预填模板，适配旧模板，保留项目草稿与固定价快照 | 方案未启用和预算不足时仍可准备，销售端仅看到可承接项目，验收后进入结算 |
| 预约与客户 | 显示项目、来源和跟进状态，会员预约由销售申请并由管理员确认或取消 | 边界明确，重复提交可恢复，销售仅处理分配给本人的客户 |
| 客户订单 | 用同一账本登记官网目录项目，绑定原客户和已确认的后续预约，可独立记录合同、币种、实收、退款与交付 | 关闭激励也可登记，未授权账号不可读写，相同来源与同一项目不会重复开有效单 |
| 验收 | 隔离数据跑前台、管理员和销售流程，全量回归，并核对生产写入范围 | 真实台账不产生测试数据，本地交付与生产状态可区分 |

内置项目费是可微调的人民币准备价，确认模板和发布项目是两个动作。保持现行项目预算来自成熟业务已实现留存的规则。客户服务订单与伙伴本人佣金订单共用核账机制，官网目录金额只按实际合同和收款登记。历史服务案例继续使用原流程。

## 核对结果

| 路径 | 原问题 | 当前办理方式 |
| --- | --- | --- |
| 官网项目 → 预约回执 | 基础体检缺少定向入口。提交期间关闭弹窗会丢失回执 | 两侧使用同一项目编号。联系登记返回意向编号。网络超时沿用同一提交标识重试 |
| 意向 → 顾问沟通 | 客户列表主要呈现会员期限，详情缺办理阶段和沟通安排 | 按阶段、后续预约过滤，管理员在客户详情分配、登记北京时间和沟通方式，记录已沟通或取消。销售只见负责客户的安排 |
| 已确认需求 → 签约与交付 | 业务订单依赖激励产品和伙伴认证。初次旗舰咨询没有意向期次时无处确认 | 工作室服务可在激励关闭时开单。签约记录合同主体、凭证和确认服务期次，保留原意向。按合同币种核对收款、退款、成本和交付 |
| 会员后续预约 → 关联订单 | 销售可提交自由文本期次，缺管理员审核和取消顺序 | 用月份和期次选择。复核会员有效期，防止同一期重复预约。管理员核实席位后确认。存在有效订单时，先处理订单再取消预约 |
| 项目模板 → 立项 → 结算 | 空白模板阻断发布 | 内置三份可采纳的样板。方案关闭或预算为零时可做草稿。发布后按锁定工作验收，合格项目费进入月结 |
| 项目报价、权限与历史 | 官网展示价格与经营金额有不同用途。旧付款与服务案例已有记录 | 合同币种和金额由管理员根据实际凭证填写。销售仅看业务需要的字段及本人归因，原有服务案例和账单继续可读 |

本地 151 项 Node 测试已通过。隔离浏览器验证使用合成记录走过基础体检预约回执、管理员安排并完成沟通、开单、合同登记、JPY 收款和交付，以及默认模板立项，并核对销售端当前归属订单。手机宽度按 390 px 检查。退款重试、首期服务期次、关联预约取消顺序、销售改派及伙伴项目预算与验收由自动测试覆盖。

截至 2026-11-22，测试基线的官网期次窗口列出 5 个期次，按现行截止日规则均已关闭。官网顾问登记可继续办理。期次上架及内部安排需按真实席位和业务日历确认。顾问联系、席位核对及付款均由工作人员按现行流程办理。此次为本地实现与验证。
