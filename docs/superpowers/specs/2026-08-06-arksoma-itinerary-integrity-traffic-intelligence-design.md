# ARKSOMA 行程严谨性与访问情报设计

**目标：** 修正五日行程中图片、描述与来源不一致的问题；让方舟生命纪行开关直观、可审计地生效；把已有的访问日志转化为所有者可理解的访问与安全情报。

## 1. 行程：参考路径与定制交付分离

公开页面展示的是“当期参考路径”，不是不可变的服务承诺。每张行程卡保留清晰的城市、日程、图片、标题、说明和标签，并在行程区说明：项目将根据健康状态、季节、预约与接待条件确认。

行程数据改为可命名的已核验体验记录，并由期次选择引用。标准期与敬亲期共享核心顺序；敬亲期只在抵日节奏、步行强度和休息安排上覆盖。后续每月更新可对某一期次覆盖任一日，而不会影响其他期次。

初始的五日参考路径为：

1. 东京湾私席与船上怀石。
2. 医疗准备与介绍制茶舞：上午完成个人医疗安排；图片和可视内容明确对应下午的茶与舞文化接待，避免暗示图片为医疗现场。
3. 茶道私宅与一期一会。
4. 京都庭园与安静参访。
5. 香道雅集与归程协调：替换现有与文字不符的建筑图片，使用能直接表达香道接待的既有图片；将 `/all` 中同一来源的错误标题一并收敛为不夸大的表述。

页面不再以未经确认的“非公开区域”“皇室”等词替代实际确认；如果某个当期项目尚未锁定，显示为“当期定制确认”而非虚构项目名称。

## 2. 生命纪行公开开关

现有开关不保存的原因是它与价格等字段共用表单，且必须填写“修改原因”。改为独立的发布控件：当前状态清晰显示为“未公开”或“已公开”，切换后立即保存并反馈结果。服务端仍写审计记录，使用固定且可追溯的发布原因；价格等商业字段继续保留显式填写修改原因的保护。

公开接口继续只返回 `showPrivateJournal` 这一展示白名单字段。页面仍默认隐藏；只有接口确认开启才显示，接口失败继续隐藏。

## 3. 所有者访问情报

统计首页保留深色 ARKSOMA 管理视觉，增加三层信息：

- **趋势：** 同一张趋势图同时展示访问次数与独立 IP，支持日、周、月视图。
- **概览：** 今日访问、今日独立访客、累计访问、累计 IP，以及当前高风险扫描数和“正常/待观察/扫描风险”的汇总。
- **IP 情报：** 所有者专属 IP 列表，提供 IP、地区、访问次数、最后访问、访问性质和判定依据；可查看“全部”“可能真实访问”“自动化访问”“高风险扫描”。

“真实访问”不是身份认证，因此前端使用概率性用语：`可能为正常访问`、`自动化访问`、`疑似扫描`、`高风险扫描`、`信息不足`。判定以可解释的规则生成：恶意路径命中、命中比例、自动化 User-Agent、资源/页面访问模式和请求密度。每一条结论显示简短依据，避免把普通机器人或高频访客直接称为攻击者。

历史 `access.log` 只在受控后台任务中一次性回填为 IP 信号摘要；之后每次新请求增量更新。不会把 IP 数据暴露到公开端或销售端，也不会引入第三方分析平台。

## 4. 数据流与边界

`scripts/arksoma-periods.cjs` 负责期次和参考行程渲染；行程体验记录保持在仓库内，供 `/all` 与期次页使用同一语义来源。

`app.js` 负责：商业开关的独立更新接口、访问日志的信号累积、所有者统计 API 的趋势和情报输出。`admin-pro.*` 负责展示与交互。销售入口不获得流量、完整 IP、商业配置或发布权限。

已有原始访问日志不删除；统计回填仅增加可重建的汇总字段。地区查询沿用当前按需缓存机制，查询失败显示“地区待确认”，不阻塞列表。

## 5. 错误处理与验证

- 期次页若无具体覆盖，回退到已核验参考路径，并保留“当期确认”提示。
- 生命纪行切换失败，控件回退到服务端实际状态并显示失败原因。
- 流量情报回填失败不影响网站请求和现有基础统计；后台显示“情报待重建”。
- 新增回归测试：第 2、5 日图片与语义；期次覆盖；公开开关即时保存和默认隐藏；趋势双指标；风险分类和 API 权限。
- 本地测试、不同屏宽后台检查、生产部署后公开接口、期次页、所有者统计接口和 PM2 健康检查全部通过后再交付。

## 6. 非目标

- 不把公开行程变成固定医疗或文化服务承诺。
- 不新增客户侧功能或销售侧流量权限。
- 不接入付费第三方数据平台，也不自动封禁 IP；本次只做识别、展示与可解释判断。
