# ARKSOMA 会员预约制、销售培训与前后台一体化设计规格

## 1. 目标与范围

本次升级把已确认的 ARKSOMA「长寿之石」客户页面、现有顾问申请后台和月度期次任务整合为一套可持续运营的平台。

本次包含：

- 正式同步已确认的 ARKSOMA 客户前端；
- 将申请表单一次提交到现有后台订单系统；
- 建立方舟年度席位与续展规则；
- 增加销售答疑与新人培训模块；
- 增加商业配置模块；
- 增加销售账号、客户归属与权限隔离；
- 固化普通期次与每月第三期敬亲礼遇期规则；
- 更新每月 15 日的自动期次任务与安全部署验收。

本次不建设在线支付、短信平台、复杂考试积分、多人实时协作或外部 CRM。付款与退款仍由线下流程处理，后台只记录业务结果。

## 2. 统一品牌与预约叙事

品牌固定为 `ARKSOMA · 方舟计划`。服务采用会员预约制，对外不使用“交会员费才能购买”的促销式表达，而使用：

- `ARKSOMA PRIVATE ACCESS · BY APPOINTMENT`
- `方舟年度席位 · 仅接受预约申请`

核心说明：

> 每一期仅接受少量预约申请，以确保专业评估、医疗协调与在日接待在抵达前完成准备。未经提前沟通与专业评估，日本机构可能无法接收当次申请。

页面必须保持医疗边界：年度席位提供顾问、协调、资料连续性、档期与在日服务，不代表保证获得治疗。最终医疗安排必须由日本专业机构评估确认。

## 3. 方舟年度席位规则

### 3.1 激活与有效期

- 普通完整方案默认价格为 `RMB 580,000 / 人`。
- 完整方案确认后自动激活 12 个月方舟年度席位。
- 有效期采用从激活日开始的滚动 12 个月，不采用自然年度。
- 订单必须保存成交时的价格快照；以后修改配置不得改变历史订单。

### 3.2 有效期内延续

客户在席位有效期内确认下一期完整方案时：

- 保留原销售和私人顾问；
- 由所属销售以私人医疗秘书身份全权协调，不要求客户再次进入公开页面填写申请；
- 保留经客户授权的连续服务资料；
- 获得优先评估与档期协调，但不承诺一定接诊；
- 当前到期日顺延 12 个月，而不是从新订单日期重新计算；
- 无需另付当期年度服务费。

客户暂不确认下一期完整方案，但希望保留连续权益，可在到期前支付年度服务费，默认 `RMB 19,800`，从当前到期日顺延 12 个月。

### 3.3 到期规则

- 到期未延续的客户保留历史订单，但失去优先档期、原顾问连续负责和续展礼遇。
- 到期后再次申请时按新客户重新评估。
- 到期后不能只补交年度服务费恢复原权益；再次确认完整方案后重新激活新的 12 个月席位。

### 3.4 固定权益

1. 原销售与私人顾问连续负责；
2. 私人医疗秘书代办后续预约，无需重复提交公开申请；
3. 优先评估与有限档期协调；
4. 经授权的连续资料管理，重要健康资料仍须按当期情况更新；
5. 住宿、饮食、陪同、文化体验与同行偏好的连续定制；
6. 有效期内确认下一期完整方案，年度席位自动顺延并免收当期年度服务费。

后台会员状态固定为：`未激活`、`有效`、`60天内到期`、`30天内到期`、`7天内到期`、`已到期`。

## 4. 期次与敬亲礼遇期

### 4.1 普通期次

- 每月第一期、第二期为普通期次；
- 默认价格 `RMB 580,000 / 人`；
- 默认内部容量为 5 席；
- 对外仅显示“少量席位”或当前可申请状态，不公开后台真实容量。

### 4.2 每月第三期

每月第三期固定命名为“敬亲礼遇期”，对外叙事围绕孝敬父母与尊老传统，不使用廉价促销语气。

- 默认价格 `RMB 560,000 / 人`，比普通期低 `RMB 20,000`；
- 行程适当简化，把体力消耗更大的安排替换为舒缓、私密和适合长辈的内容；
- 内部最大容量为 6 位；
- 对外表达为“仅开放 3 组家庭席位”，不显示“6人”；
- 默认建议两位父母或长辈同行，也接受一位长辈单独申请；
- 一组家庭席位可以是 1 位或 2 位，后台按真实人数占用容量；
- 价格、家庭组数和最大人数均可由所有者在后台覆盖。

推荐公开文案：

> 敬亲礼遇期为父母与长辈预留三组家庭席位。行程减少不必要的奔波，以更从容的节奏完成专业安排与在日体验。以两位同行为建议，亦接受单人申请。

人数增加不作为公开卖点。三组家庭席位同时保留稀缺感、家庭叙事和实际运营弹性。

## 5. 后台信息架构

后台入口继续只使用 `/admin-pro`，`/admin` 保持 404。后台固定为五个模块：

1. **访问统计**：访问趋势、来源、页面与异常请求；
2. **客户管理**：顾问申请、附件、分配销售、进度、会员期限与操作记录；
3. **销售答疑**：按服务流程组织的标准答疑、快速搜索与新人训练；
4. **商业配置**：价格、席位、会员期限、提醒和公开文案；
5. **团队权限**：销售账号、启停、密码重置、客户归属与权限审计。

黑金视觉、侧边导航、数据卡片、账本表格和右侧详情抽屉延续已确认版本，不重新设计视觉语言。

## 6. 账号与权限

### 6.1 角色

第一版只保留两种角色，避免复杂化：

- **所有者**：可访问全部五个模块、全部客户与附件；
- **销售**：后台只显示“客户管理”和“销售答疑”，且只能访问自己负责的客户和已发布答疑内容。

### 6.2 登录方式

所有者保留现有个人习惯：进入 `/admin-pro` 后只输入管理员密码，不要求用户名。管理员密码继续从服务器私有环境配置读取，不写入网页或数据文件。

销售使用“用户名 + 密码”登录。两类登录共用 `/admin-pro`：

- 默认显示“管理员登录”，界面只有密码输入框；
- 通过低调的“销售登录”切换后，才显示用户名与密码；
- 登录成功后由服务端会话确定角色，不能由前端自行选择角色；
- 所有者登录后显示五个模块；
- 销售登录后导航中只存在“客户管理”和“销售答疑”。

销售账号不得使用管理员密码兜底，也不能通过留空用户名被识别为管理员。连续失败登录需要有界限流和审计记录，但不得在错误信息中暴露用户名是否存在。

### 6.3 销售权限

销售可以：

- 查看自己负责客户的联系方式、申请内容和附件；
- 下载自己负责客户的附件；
- 更新自己负责客户的跟进状态和销售备注；
- 为有效会员创建“内部续约预约”，选择期次、同行人数、资料更新状态和协调备注；
- 以私人医疗秘书身份推进自己负责客户的评估准备、档期确认和在日安排；
- 使用流程学习、快速应答和情景训练；
- 修改自己的密码。

销售不可以：

- 查看其他销售的客户、资料或附件；
- 修改客户归属；
- 为已到期客户绕过新客户重新评估规则；
- 编辑答疑标准答案；
- 修改价格、席位或会员规则；
- 创建、禁用或重置其他账号；
- 查看完整访问安全数据。

隐藏导航不是权限边界。访问统计、商业配置、团队权限及其他销售客户的所有 API 都必须由服务端返回 403；销售不能通过直接输入接口地址访问。

### 6.4 所有者操作

所有者可以创建销售账号、设置姓名和登录名、生成初始密码、启用或停用账号、重置密码、分配或转移客户。新订单默认处于“待分配”，只有分配完成后对应销售才可访问。

密码使用随机盐的安全哈希保存，不保存明文。登录会话包含用户 ID、角色和会话版本；账号停用或密码重置后，旧会话立即失效。

所有敏感操作写入审计记录：操作者、时间、对象、动作和结果。附件下载也记录审计，但日志不得记录附件内容。

## 7. 客户与会员数据

客户订单在现有字段上增加：

- `assignedSalesId`；
- 成交价格快照和期次类型；
- 真实同行人数与占用家庭组；
- 会员激活日、到期日和计算状态；
- 完整方案确认次数；
- 年度服务费续展次数；
- 会员事件历史；
- 客户授权的连续资料标记；
- 销售备注和所有者备注；
- 完整操作审计。

有效会员的后续服务不再要求客户从公开页面重复申请。所属销售在客户详情中使用“建立后续预约”创建内部预约记录，填写：

- 目标期次与备选时间；
- 本次同行人数与同行关系；
- 健康资料是否需要更新；
- 日本机构评估准备状态；
- 住宿、饮食、陪同和在日偏好变化；
- 销售协调备注。

内部预约与原客户档案关联，不生成重复客户。只有预约被标记为“完整方案已确认”时才触发价格快照和会员顺延。销售可以建立和推进自己客户的内部预约，但不能手工修改会员到期日；会员日期只由规则引擎或所有者更正产生。

所有者可执行“确认完整方案并激活/顺延”“年度服务费续展”“手工更正”三类会员操作。手工更正必须填写原因，且不得覆盖历史事件。

## 8. 销售答疑与培训系统

### 8.1 服务流程顺序

答疑按客户旅程固定为十二个阶段：

1. 品牌与服务定位；
2. 为什么必须提前预约；
3. 为什么日本机构可能无法接诊；
4. 专业评估与医疗边界；
5. 完整方案价格与包含内容；
6. 方舟年度席位；
7. 有效期内继续预约的权益；
8. 年度服务费与到期规则；
9. 健康资料准备与隐私；
10. 敬亲礼遇期和同行安排；
11. 抵达前、在日期间与结束后的服务流程；
12. 后续安排、续展与重新申请。

第一版预置不少于 28 条完整答疑，覆盖上述全部阶段。涉及日本医疗接收规则的内容必须附权威来源与核对日期。

### 8.2 单条答疑结构

- 客户常见问法；
- 推荐短答；
- 完整解释；
- 必须传达的信息；
- 禁止使用的表达；
- 适用阶段、关键词与标签；
- 权威来源链接与核对日期；
- 草稿或已发布状态；
- 排序、创建人与最后修改时间。

所有者可以添加、编辑、排序、发布、停用和复制答疑。销售只能阅读已发布内容。

### 8.3 三种使用模式

- **流程学习**：按十二阶段顺序学习完整服务闭环；
- **快速应答**：按“预约、价格、不接诊、会员、资料、敬亲”等关键词搜索并复制推荐短答；
- **情景训练**：先显示客户问题，销售思考后展开标准答案、必须信息和禁用表达。

第一版不做考试分数、排行榜或强制学习进度。

## 9. 商业配置

默认配置如下：

- 普通完整方案价格：`580000`；
- 年度服务费：`19800`；
- 年度席位有效期：`12` 个月；
- 普通期次内部容量：`5`；
- 敬亲礼遇期价格：`560000`；
- 敬亲礼遇期家庭组数：`3`；
- 敬亲礼遇期最大人数：`6`；
- 到期提醒：`60 / 30 / 7` 天；
- 是否在客户页面显示价格；
- 会员说明和敬亲礼遇期公开文案。

配置支持单个期次覆盖默认价格、人数、组数、截止日期和可申请状态。每次修改必须记录旧值、新值、操作者、时间和修改原因。

公开前端只读取经过白名单筛选的公开配置接口；账号、内部容量、客户资料和后台备注不得出现在公开接口。前端保留安全的静态默认值，接口短暂失败时页面仍可使用。

## 10. 客户前端

正式前端以已通过 QA 的 `prototype/arksoma-v2` 为交互目标：

- 保持长寿之石、细胞纹理、黑金视觉和逐模块滚动；
- 保持经纬度菜单、固定期次面板、横版行程卡片和一次提交申请；
- 首屏增加克制的 `PRIVATE ACCESS · BY APPOINTMENT`；
- 价格旁显示“已包含首个 12 个月方舟年度席位”；
- 服务协议模块解释预约制、专业准备与有限资源；
- 第三期自动切换为敬亲礼遇期文案、价格与三组家庭席位表达；
- 申请表单把资料和最多 3 个附件一次提交到现有后台接口；
- 公开申请主要服务新客户、已到期客户和没有所属销售的客户；有效会员由私人医疗秘书从后台续办；
- 成功后只显示订单编号、申请期次和后续联系说明，不增加第二次操作；
- iPhone、大屏手机、iPad 竖横屏和三折叠设备均不得出现横向溢出或弹层裁切。

## 11. 数据存储与安全

继续采用 VPS 私有目录和原子 JSON 写入，符合当前低并发规模并避免引入数据库运维。新增独立文件：

- `staff.json`：账号与密码哈希；
- `knowledge-base.json`：答疑内容；
- `business-config.json`：商业配置；
- `audit-log.jsonl`：追加式审计事件；
- 现有客户订单和附件目录继续使用。

所有文件位于静态网站目录之外，权限保持 `700/600`。API 必须在服务端按角色和客户归属校验，不能只依赖前端隐藏按钮。

## 12. 月度自动任务

每月 15 日 09:00 的任务保持执行时间不变，提示词和验收项更新为：

1. 先读同一自动任务的最新 memory、检查 Git 状态和生产运行面；
2. 若发现月度生成范围之外的未确认改动，停止部署；
3. 运行完整测试、风险回归和期次 dry-run；
4. 生成下月三期和下下月两期；
5. 自动确认每月第三期为敬亲礼遇期；
6. 校验价格、会员文案、家庭组规则、图片和无占位符；
7. 本地验证期次面板、经纬度菜单、行程卡片和申请表单；
8. 在临时私有目录测试申请与附件，禁止向生产后台创建测试订单；
9. 检查手机、iPad 和宽屏无横向溢出；
10. 验证 `/admin` 为 404、`/admin-pro` 为 200、未登录后台 API 为 401；
11. 只有全部通过才执行受控部署；
12. 上线后复验首页、五个期次、公开配置、后台入口、PM2 和错误日志；
13. 将结论、变更、风险和下次重点写回同一 automation memory。

## 13. 错误处理

- 公开配置加载失败：使用页面内安全默认值，不阻断申请；
- 申请失败：保留用户已填内容，显示明确原因，不生成重复订单；
- 附件失败：说明具体文件和限制，不提交半成品订单；
- 销售越权：服务端返回 403，同时写入审计事件；
- 会员日期异常：禁止保存并要求所有者填写更正原因；
- 配置保存失败：旧配置保持生效；
- 自动任务遇到意外 Git 改动、测试失败或远端不同步：停止部署。

## 14. 验收标准

- 所有者可管理五个后台模块；
- 所有者沿用密码单字段登录，销售使用用户名和密码登录；
- 销售后台只显示客户管理与销售答疑两个模块；
- 两个销售账号无法互相查看客户、附件或备注；
- 销售直接请求无权限模块 API 时返回 403；
- 有效会员可由所属销售建立内部续约预约，无需再次填写公开页面；
- 销售可完整使用已发布的答疑和训练内容；
- 普通方案、年度服务费和敬亲礼遇期价格可配置并保留历史快照；
- 有效期内完整方案和年度服务费两条顺延路径计算正确；
- 过期客户不能只补年度服务费恢复权益；
- 第三期对外显示三组家庭席位，内部最多 6 位且允许单人；
- 客户一次提交后在后台生成一个订单，附件可由有权限人员下载；
- `/admin` 始终为 404，越权 API 返回 403，未登录 API 返回 401；
- 正式前端通过手机、iPad、宽屏与交互设计 QA；
- 月度自动任务能生成新窗口并在任何关键验证失败时停止部署。
