# ARKSOMA 原生滚动与轻量进入动效设计

## 目标

在不改变页面结构、内容密度和主要交互的前提下，完成三项定点优化：

1. 删除申请弹窗中面向内部实现的说明文案。
2. 将坐标字形柔光时长延长约 10%–15%。
3. 用稳定的原生滚动和一次性进入动效替代偶发吸附与持续滚动计算，形成克制、顺滑的苹果式层次感。

## 申请弹窗

- 删除：`资料与附件一次提交并直接生成私密申请订单，无需跳转或重复操作。`
- 不增加替代文案，不留下多余间距。
- 保留标题、单次服务价格、连续方案说明、表单字段和一次提交后台的功能。

## 坐标柔光

- 动画时长从 `0.9s` 调整为 `1.02s`，增加约 13%。
- 保持现有 `1.1s` 入场延迟、亮度、色彩、字形裁切、单次播放和静止状态。
- 不增加循环、外部光线、下划线或其他装饰。

## 滚动体验

### 移除

- 移除根页面的 `scroll-snap-type`。
- 移除主要模块的 `scroll-snap-align`。
- 移除依赖 `animation-timeline: view()` 的行程大图持续滚动动画。

这些机制分别造成“只有接近边界时才吸附”的不一致反馈，以及移动设备滚动时持续计算大图变换的额外负担。

### 保留与增强

- 用户滚轮、触摸滑动继续使用浏览器原生滚动，不由 JavaScript 接管。
- 锚点跳转继续使用现有平滑滚动；普通触摸和滚轮不增加人为惯性。
- 已有主要内容块进入视口时执行一次淡入和轻微上移归位；位移从 `18px` 收敛为约 `12px`，保持克制。
- 行程卡片不整体隐藏。卡片进入视口时，仅图片从约 `1.018` 倍和轻微降亮度归位到正常状态，时长约 `0.9s`，每张只运行一次。
- JavaScript 或观察器不可用时，行程图片直接显示最终状态；直接访问 `#itinerary` 时内容不会变黑或不可见。

## 性能与无障碍

- 不监听连续 `scroll` 事件，不逐帧读取布局，不接管滚轮或触摸手势。
- 使用单个 `IntersectionObserver` 管理一次性进入状态，完成后取消观察。
- 动画仅改变 `opacity`、`transform` 和轻度滤镜，避免布局重排。
- `prefers-reduced-motion: reduce` 下所有内容直接显示最终状态。
- 390px、768px、1024px、1440px 均不得出现横向溢出或内容消失。

## 验证

1. 先增加失败测试，锁定弹窗文案删除、`1.02s` 坐标动画、无滚动吸附、无 `animation-timeline: view()`。
2. 增加行程卡片一次性进入状态测试，并验证无观察器和低动态回退。
3. 运行完整自动化测试。
4. 在手机、iPad 和桌面视口实际滚动，确认没有拖拽感、偶发吸附或控制台错误。
5. 通过本地验证后才部署；线上再次检查页面、申请弹窗、后台入口、权限边界和 PM2 状态。

## 非目标

- 不改页面模块顺序、图片、字体、价格、会员规则、期次逻辑或后台功能。
- 不实现强制整屏分页、滚轮劫持、复杂视差、循环动画或新的动画依赖。
